# Phase 2: API and Database Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `CustomGolfStats.Api`, the ASP.NET Core API over PostgreSQL that the Uno app (phase 5), the Astro site (phase 4) and the golftrack migration tool (phase 3) all use. It owns accounts and auth, courses (search, import, versioning, flags), rounds and sync, weather, stats and admin. It also produces an OpenAPI document and a generated typed C# client.

**Architecture:** .NET 10 minimal APIs organised as feature folders (`Features/Auth`, `Features/Me`, `Features/Courses`, `Features/Rounds`, `Features/Stats`, `Features/Admin`). Each folder exposes one `AddXFeature(IServiceCollection)` and one `MapXEndpoints(IEndpointRouteBuilder)` extension, which `Program.cs` calls, so parallel tasks never edit the same file. EF Core (Npgsql) with a single `AppDbContext` that also holds ASP.NET Core Identity. External services (GolfCourseAPI, weather, Apple/Google token validation, clock) sit behind interfaces and are faked in tests. All golf rules come from `CustomGolfStats.Domain`; the API never re-implements them.

**Tech Stack:** .NET 10, ASP.NET Core minimal APIs, EF Core 10 + Npgsql, ASP.NET Core Identity (bearer tokens via `MapIdentityApi`-style endpoints), Microsoft.AspNetCore.OpenApi, NSwag (client generation), xUnit v3 + `Microsoft.AspNetCore.Mvc.Testing` + Testcontainers.PostgreSql.

**Spec:** `docs/superpowers/specs/2026-11-10-custom-golf-stats-v1-design.md` (§2, §3, §5, §6, §7, §8, §10). Roadmap: `docs/superpowers/plans/2026-11-11-v1-roadmap.md` (includes phase 1 carry-overs).

## Global Constraints

- Everything from phase 1 still applies (`Directory.Build.props`: net10.0, nullable, warnings as errors). `CustomGolfStats.Domain` keeps **no package references**.
- Add `Directory.Packages.props` (central package management). No package versions in csproj files.
- No FluentAssertions, no AutoMapper, no MediatR. Plain `Assert`, hand-written mapping.
- Database: PostgreSQL 17. Table and column names in snake_case (`EFCore.NamingConventions`). Enums stored as strings. Timestamps are `DateTimeOffset` stored as `timestamptz` (UTC). Dates played are `DateOnly`.
- Every request DTO is a `record` in the feature folder. Entities are never returned from endpoints.
- Errors are RFC 7807 problem details. Validation failures return 400 with `ValidationProblem` keyed by field (for hole/shot errors use keys like `holes[3].shots[1]` and the domain error enum name as the message).
- Ownership: a golfer can only read or change their own rounds, handicap entries and flags. Another golfer's round returns **404**, not 403.
- Admin endpoints require the `Admin` role policy on the whole route group. Tests prove a `User` gets 403 on every admin route.
- Secrets (GolfCourseAPI key, weather key, Apple/Google client IDs, connection string, signing keys) come from configuration/environment only. `appsettings.Development.json` may hold a local connection string, nothing else secret.
- Time comes from `TimeProvider` (registered as `TimeProvider.System`; tests use `FakeTimeProvider`).
- The API calls GolfCourseAPI only from `courses/provider-search` and `courses/import`. Nothing else reads from the provider.

## Review Focus

1. **Tee versioning:** a round is tied to the `TeeVersion` in effect on the date played. Creating a new version never changes older rounds' stats. Correcting a version in place (admin) does. Editing a version that no round uses is always allowed in place. Tests in Task 4.
2. **Sync and last write wins:** an older `ClientUpdatedAt` never overwrites a newer one; a stale push gets 409 with the current server copy. Soft deletes sync. `sync/changes?since=` never misses a write made during the same request window (cursor is server time captured *before* the query, filter on server-set `ModifiedAt`). Tests in Task 5.
3. **Trial counting:** a Free golfer's first push of a new shot-by-shot round increments `TrialShotRoundsUsed` once, even if pushed again or edited later, and the round is stored even when the trial is used up. Paid golfers never increment. Tests in Task 5.
4. **Derived hole summaries:** for shot-by-shot rounds the server ignores client-sent hole summary fields and re-derives them with `HoleSummaryDeriver` from the tee version's hole info; quick rounds are validated with `HoleSummaryValidator`. Tests in Task 5.
5. **Authorization:** every non-auth endpoint requires a signed-in user; another golfer's data is invisible; admin routes reject users. Tests in Tasks 3, 5, 6, 7.

### Task 1: API skeleton, database schema and test harness (sequential, before everything else)

**Files:** everything under `Data/`, `Infrastructure/`, `Program.cs`, csproj files, `Directory.Packages.props`, `slnx`, test `Infrastructure/`, and one empty `XFeature.cs` per feature folder with `AddXFeature` / `MapXEndpoints` stubs.

**Produces:**
- Entities exactly per spec §5 and §6, plus:
  - `Account : IdentityUser<Guid>` with `Role` (domain enum, string), `Tier`, `TrialShotRoundsUsed`, `FirstName`, `LastName`, `Gender` (`Male|Female|Unspecified`), `GhinNumber?`, `HomeCourseId?`, `Units` (`Yards|Meters`, default Yards), `DisabledAt?`, `CreatedAt`.
  - `Course`: `Name`, `ClubName?`, `Address?`, `City?`, `Region?`, `Country?`, `Phone?`, `Website?`, `Latitude?`, `Longitude?`, `Status` (`Imported|UserEdited|Verified`), `Source` (`GolfCourseApi|Manual|Golftrack`), `ProviderCourseId?` (unique per source when not null), `LastVerifiedAt?`, `MergedIntoCourseId?`, `CreatedAt`, `UpdatedAt`.
  - `Tee`: `CourseId`, `Name`, `Gender`.
  - `TeeVersion`: `TeeId`, `EffectiveFrom` (DateOnly), `Par`, `Rating`, `Slope`, `FrontPar?`, `FrontRating?`, `FrontSlope?`, `BackPar?`, `BackRating?`, `BackSlope?`, `Source`, `ChangedByAccountId?`, `ChangedAt`. Unique `(TeeId, EffectiveFrom)`.

  - `Round`: `Id` (client GUID, not generated), `AccountId`, `TeeVersionId`, `PlayedOn` (DateOnly), `StartedAt?`, `FinishedAt?`, `EntryMode`, `RoundType` (`Practice|Casual|Tournament|League`, default Casual), `Notes?`, `WeatherConditions?`, `TemperatureF?`, `WindSpeedMph?`, `WindDirectionDegrees?`, `LegacyWeather?`, `DurationMinutes?`, `DistanceMiles?`, `StepCount?`, `ClientUpdatedAt`, `ModifiedAt` (server-set), `DeletedAt?`, `Version` (int concurrency counter), `TrialCounted` (bool).   - `HoleResult`: per spec, plus `Id` (Guid), unique `(RoundId, EntrySequence)`.
  - `ShotEntity`: per spec §6, `HoleResultId`, unique `(HoleResultId, Sequence)`.

### Task 2: Auth (wave 2)

**Files:** `Features/Auth/*`, `tests/.../Auth/*`.

- `POST /auth/register`, `/auth/login`, `/auth/refresh` using Identity's bearer token handler (`MapIdentityApi<Account>` mapped under `/auth`, with the unused confirm/2FA/manage routes excluded or left default but documented). Login of a disabled account fails with 401.
- `POST /auth/external` `{ provider: "apple"|"google", idToken, firstName?, lastName? }`: validates the ID token through `IExternalTokenValidator` (real implementation validates signature, issuer, audience and expiry against Apple's / Google's OIDC metadata using `Microsoft.IdentityModel.Protocols.OpenIdConnect`; audiences from config). Finds the account by external login, else by verified email (links the login), else creates one. Returns the same token response as `/auth/login`.
- Tests: register + login + refresh round trip; wrong password 401; disabled account 401; external sign-in creates then reuses an account; external token for an existing email links rather than duplicates; invalid external token 401.

### Task 3: Me (wave 2)

**Files:** `Features/Me/*`, tests.

- `GET/PUT /me` profile (names, gender, GHIN number, home course id (must exist), units).
- `GET /me/handicap`, `POST /me/handicap`, `DELETE /me/handicap/{id}` (index between -10.0 and 54.0).
- `GET /me/entitlements` → `{ tier, role, features: { shotByShotEntry: bool }, trialShotRoundsRemaining: int? }` computed with `Entitlements` and the `TrialShotRounds` setting.
- Tests: profile update persists; invalid home course 400; handicap CRUD and ownership (another golfer's entry 404); entitlements for Free with 0/3/5 used and for Paid; unauthenticated 401.

### Task 4: Courses (wave 2)

**Files:** `Features/Courses/*`, tests.

- `ICourseProvider { Task<IReadOnlyList<ProviderCourseSummary>> SearchAsync(string query, CancellationToken); Task<ProviderCourse?> GetAsync(string providerCourseId, CancellationToken); }`.
- `GolfCourseApiProvider` (typed `HttpClient`, base `https://api.golfcourseapi.com/v1/`, header `Authorization: Key {key}`; `GET search?search_query=`, `GET courses/{id}`). Maps `club_name`, `course_name`, `location{address,city,state,country,latitude,longitude}`, `tees{male[],female[]}` each with `tee_name, course_rating, slope_rating, par_total, front_course_rating, front_slope_rating, back_course_rating, back_slope_rating, holes[{par,yardage,handicap}]`. Unit-test the mapping from a recorded JSON sample in the test project.
- `GET /courses?query=&near=lat,lon` searches our database (name/city, case-insensitive, excludes merged courses).
- `GET /courses/provider-search?query=` → provider results, each marked `alreadyImported` with our course id when present.
- `POST /courses/import { providerCourseId }` → imports one course (Status `Imported`, Source `GolfCourseApi`, one `TeeVersion` per tee with `EffectiveFrom = 1900-01-01`); importing an already-imported id returns the existing course (200) without calling `GetAsync` again.
- `GET /courses/{id}` → course, tees, and each tee's versions with holes (current version flagged).
- `POST /courses` manual create (Source `Manual`, Status `UserEdited`) with tees and holes; validates hole numbers unique, par 3–6, stroke index unique 1..n.
- `PUT /courses/{id}` details; `POST /courses/{id}/tees/{teeId}/versions` new version with `EffectiveFrom`; `PUT /courses/{id}/tees/{teeId}/versions/{versionId}` in-place edit **only when no round uses the version** (otherwise 409 telling the caller to create a new version or ask an admin). Non-admin edits to a `Verified` course create a `CourseFlag` with the proposed change in the note and return 202; edits to other courses apply and set Status `UserEdited`.
- `POST /courses/{id}/flags { teeId?, holeNumber?, note }`.
- `TeeVersionService.ResolveAsync(teeId, DateOnly playedOn)` → latest version with `EffectiveFrom <= playedOn` (falls back to the earliest version). Used by Task 5.
- Tests: search, provider search marks imported, import is idempotent, manual create validation, version resolution by date, in-place edit blocked when used, verified-course edit becomes a flag, flags stored.

### Task 5: Rounds, sync and weather (wave 2)

**Files:** `Features/Rounds/*`, tests. Depends on Task 4's `TeeVersionService` signature only; until it lands, code against the signature above.

- `PUT /rounds/{id}` upsert whole round: `{ teeId, playedOn, startedAt?, finishedAt?, entryMode, roundType, notes?, weather fields?, durationMinutes?, distanceMiles?, stepCount?, clientUpdatedAt, holes: [{ holeNumber, entrySequence, score?, putts?, fairwayHit?, teeShotLeft?, ..., shots?: [...] }] }`.
  - Resolves `TeeVersionId` from `teeId` + `playedOn` on create; keeps it on update unless `teeId` or `playedOn` changed.
  - Quick: validates each hole with `HoleSummaryValidator` (par from the tee version's hole). Shot-by-shot: validates shots with `ShotValidator`, derives the summary with `HoleSummaryDeriver.Derive(HoleInfo, entrySequence, shots)`, stores `IsDerived = true`.
  - A hole number not on the tee version → 400.
  - Last write wins: if the stored `ClientUpdatedAt` is newer than the incoming one → **409** with the server copy. Equal or older stored → replace header, hole results and shots; `Version++`; `ModifiedAt = now`.
  - Trial: on first create of a `ShotByShot` round by a `Free` golfer, `TrialShotRoundsUsed++` and `TrialCounted = true` in the same transaction. Never again for that round. Never for Paid.
  - Missing weather with `startedAt` and course coordinates → fill from `IWeatherProvider` after save (failure is logged and ignored).
- `GET /rounds?year=` list (summary: date, course, tee, holes, score, to par), `GET /rounds/{id}` full round with shots, `DELETE /rounds/{id}` soft delete (`DeletedAt`, `ModifiedAt = now`).
- `GET /sync/changes?since=` → `{ serverTime, rounds: [full rounds incl. deleted ones as tombstones], courses: [courses used by those rounds, full], handicapEntries, entitlements }`; `since` omitted → everything.
- `GET /weather?lat=&lon=&at=` → `{ conditions, temperatureF, windSpeedMph, windDirectionDegrees }` via `IWeatherProvider`. `OpenMeteoWeatherProvider` uses Open-Meteo forecast for times within the last 5 days and the archive API before that; base URLs and optional API key from config (commercial plan URL is configuration, not code).
- Tests: create/read quick round; derived summaries for shot round ignore client summary values; invalid shots 400 with keyed errors; stale push 409; newer push replaces; soft delete appears in changes as tombstone; changes cursor; trial increments once and round still stored when exhausted; paid never increments; another golfer's round 404 on get/put/delete; weather filled on sync with fake provider.

### Task 6: Stats (wave 2)

**Files:** `Features/Stats/*`, tests. Seeds data through `AppDbContext` directly in tests, so it does not wait for Task 5.

- `RoundDataLoader.LoadAsync(accountId)` → `IReadOnlyList<RoundData>` (excludes soft-deleted rounds; course and tee **names from the current entities**; par per hole from the round's tee version).
- `GET /stats/years` (years with rounds), `GET /stats/{year}/overall` (tiles + latest handicap index on or before year end), `/season`, `/results`, `/scoring`, `/off-the-tee`, `/approach`, `/putting`, `GET /stats/career`, `GET /stats/courses?year=`, `GET /stats/handicap` (history), `GET /rounds/{id}/scorecard` (holes with par, yardage, stroke index from the round's tee version, plus hole results).
- Response DTOs mirror the domain section records; `Ratio`/`Average` serialise as `{ value, numerator, denominator }` (or the domain's equivalent fields).
- Tests: each endpoint returns numbers matching a direct domain call on the same seeded data; empty year returns nulls not errors; renamed course shows new name; deleted rounds excluded; another golfer's rounds never included.

### Task 7: Admin (wave 3, after Tasks 4–5 are merged)

**Files:** `Features/Admin/*`, tests.

- `GET /admin/users?query=`, `PUT /admin/users/{id}` (tier, role, disabled). An admin can't remove their own admin role.
- `GET /admin/courses?status=`, `PUT /admin/courses/{id}` (details), `PUT /admin/courses/{id}/tees/{teeId}/versions/{versionId}` (in-place correction allowed even when used), `POST /admin/courses/{id}/verify` (Status `Verified`, `LastVerifiedAt = now`), `POST /admin/courses/{id}/merge { intoCourseId }` (moves rounds by matching tee name + version effective date where possible, else 409 listing unmatched tees; marks source `MergedIntoCourseId`).
- `GET /admin/flags?status=Open`, `POST /admin/flags/{id}/resolve|dismiss`.
- `GET/PUT /admin/settings` (`TrialShotRounds`, integer ≥ 0).
- Tests: 403 for a User on every admin route (enumerate the route table); tier change reflects in `/me/entitlements`; correction changes a used version's stats; merge moves rounds; flags resolve.

### Task 8: OpenAPI document, generated client and CI (wave 3)

**Files:** `src/CustomGolfStats.Api.Client/*`, Api csproj (build-time document generation), CI.

- API build writes `openapi/CustomGolfStats.Api.json` (`Microsoft.Extensions.ApiDescription.Server`) into the client project; the file is committed. Every endpoint has a name (`WithName`) and typed results so the document has real schemas.
- Client project generates `CustomGolfStatsApiClient` with NSwag (`NSwag.ApiDescription.Client`, `System.Text.Json`, nullable). It references nothing from the API.
- A test asserts the committed document equals what the running API serves (`/openapi/v1.json`), so drift fails CI.
- CI: unchanged `dotnet test` command; confirm it runs Testcontainers on `ubuntu-latest`.
