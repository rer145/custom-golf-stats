# Phase 5: Uno App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The iOS and Android app (spec §3.1–§3.4, §7): sign in, local offline storage, sync, quick and shot-by-shot round entry, automatic weather/duration/steps/distance, round summary, scorecard, the Overall stats section, course import and offline manual courses.

**Architecture:** Two projects.
- `CustomGolfStats.App.Core` (plain `net10.0` class library, no Uno, no platform code): local store, sync engine, API access through the generated `CustomGolfStatsApiClient`, entitlement cache, and every view model (CommunityToolkit.Mvvm). Platform capabilities are interfaces (`ISecureStore`, `IPedometer`, `ILocationOnce`, `IConnectivity`, `IClock`). Fully unit-tested with no device.
- `CustomGolfStats.App` (Uno Platform single project, `net10.0-ios;net10.0-android;net10.0-desktop`; WebAssembly is phase 7): XAML views bound to the Core view models, navigation, theme resources from the brand tokens, and the platform implementations of the interfaces.

Local storage is SQLite through `sqlite-net-pcl` (AOT/trim friendly on iOS), with a schema that mirrors the API's round/hole/shot shapes plus cached courses, entitlements and sync state.

**Tech Stack:** .NET 10, Uno Platform 6 (Uno.Sdk), CommunityToolkit.Mvvm, sqlite-net-pcl, the generated API client, xUnit v3.

**Spec:** `docs/superpowers/specs/2026-11-10-custom-golf-stats-v1-design.md` §2, §3.1–§3.4, §6, §7. Brand: `brand/BRAND.md`. API contract notes: roadmap "Carried over from phase 2/3" (send `nextSince` back as `since`; PUT /me is full replace; a push without weather keeps stored weather; client-generated course/tee ids; scorecard order; deleted rounds are final).

## Global Constraints

- All golf rules come from `CustomGolfStats.Domain` (GIR suggestion, shot validation, hole-summary derivation, round length, entitlements, stats). Core never re-implements them.
- Offline first: creating, editing and finishing a round never needs a connection. Round ids are client GUIDs. Every local change marks the round dirty with `ClientUpdatedAt = now`.
- Sync: push each dirty round with `PUT /rounds/{id}`; on 200 store the server copy and clear dirty; on 409 replace the local round with the server copy (server wins when newer) and surface a "updated from another device" notice; deleted rounds push `DELETE` and become local tombstones. Pull with `GET /sync/changes?since=<stored nextSince>` and upsert rounds (by id + version), courses, handicap entries and entitlements; store the returned `nextSince`. Duplicates are expected and harmless.
- Entitlements: cached; starting a shot-by-shot round offline uses the cached `trialShotRoundsRemaining` (decrement locally, server is the source of truth on next sync). If shot-by-shot isn't allowed, the option is shown disabled with the reason.
- Shot entry: start lie and distance prefill from the previous shot's end; putts are in feet on the green, everything else yards; penalty strokes ≥ 0 unlimited; the hole summary shown live is `HoleSummaryDeriver.Derive`. Quick entry suggests GIR with `GirRule.Suggest` and lets the golfer override it.
- Round extras: weather fetched via the API `/weather` at round start when online (course coordinates, else one coarse location reading); duration from start/finish; steps and distance from the pedometer; all optional and editable; never block the round.
- Tokens only in `ISecureStore` (Keychain / Android Keystore-backed storage). Never log tokens.
- Brand: theme resources generated from `brand/tokens/tokens.json` (light and dark), fonts from `brand/fonts`, app icons and splash from `brand/ios` and `brand/android/res` (the RN instructions translate to Uno's `UnoIcon`/`UnoSplashScreen` or native asset copies), 44pt touch targets, round header band in Fairway Ink with the score.
- Tests: Core is TDD with xUnit v3 (in-memory or temp-file SQLite, fake API via a stub `HttpMessageHandler` serving OpenAPI-shaped JSON). The App project builds for iOS and Android with zero warnings; screens are verified on the iOS Simulator and an Android emulator with screenshots in the report.

## Review Focus

1. **Sync never loses data:** dirty rounds survive restarts; 409 handling; tombstones; pull cursor stored only after a successful pull; a failed push leaves the round dirty. Tests in Task 2.
2. **Shot entry correctness:** prefill, feet vs yards, penalties, holed shots, chip-ins, re-tees; the live summary equals the domain's derivation. Tests in Task 3.
3. **Offline trial logic** matches spec §2. Tests in Task 2/3.
4. **No tokens in logs or plain storage.**

### Task 1: Core skeleton and local store
- Projects (Core + tests) in the slnx, packages central. `LocalDb` with all row types, migrations by `user_version`, repositories for rounds (with holes and shots), courses (with tees, versions, holes), handicap, entitlements, sync state.
- Mapping between rows and domain records (`HoleInfo`, `Shot`, `HoleSummary`, `RoundData`).
- Tests: round trip of a full shot-by-shot round; dirty flag; tombstones; schema upgrade from an empty file.

### Task 2: API access, auth and sync engine
- Token storage via `ISecureStore`, login/register/refresh/sign-out, Apple/Google external sign-in call (`/auth/external` with an ID token supplied by the platform), automatic refresh on 401 once.
- `SyncEngine.SyncAsync()`: push dirty (PUT/DELETE), pull changes, store cursor; entitlement cache; one sync at a time; returns counts and notices.
- Tests: every Review Focus 1 and 3 case with a stub handler.

### Task 3: View models
- Sign in, home (recent rounds, sync status, start round), course picker (local search, online provider search/import, manual course offline with client ids), start round (tee, date, mode with entitlement gating, round type), quick hole entry (GIR suggestion + override, all fields, validation via `HoleSummaryValidator`), shot entry (prefill, units, holed, penalties, live derived summary, `ShotValidator` errors), round view (hole navigation by entry sequence, any number of holes, play a hole twice, finish round with duration/steps/distance capture), round summary and scorecard, overall stats (domain `SeasonStats.Overall` etc. over local rounds), profile and handicap.
- Tests: Review Focus 2 cases and each view model's commands and validation messages.

### Task 4: Uno app shell, theme and platform services (needs the .NET iOS/Android workloads and JDK 17)
- `dotnet new unoapp` configured for iOS, Android, desktop; MVVM; navigation; theme dictionaries generated from tokens (light/dark); fonts; icons and splash from the brand kit; platform services (Keychain/Keystore secure storage, CoreMotion/Android step counter, one-shot location, connectivity).

### Task 5: Screens
- XAML views for every Task 3 view model, following BRAND.md (round header band, stat tiles, buttons). Verify on the iOS Simulator and an Android emulator; screenshots in the report.

### Task 6: Final review
- Whole-branch review, fixes, roadmap update, PR.
